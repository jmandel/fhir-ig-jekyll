# Jekyll → Java replacement for the IG Publisher: TRACKER

## How we work

- **This file is the source of truth.** Read it at the start of every session and update it before ending one. If something isn't written here, assume it will be forgotten.
- **Tasks are checkboxes with IDs** (`P1.3` etc.). States: `[ ]` todo, `[~]` in progress, `[x]` done, `[-]` dropped (say why). Never delete a task; mark it done or dropped.
- **New discoveries go straight onto the list.** When work turns up a bug, an unknown, or a new feature in use, add a task (or an Open Question) right away, in the phase it belongs to, with a one-line note on where it came from. Don't keep it in your head "for later".
- **Keep notes as we learn.** Each completed task gets a short dated entry in the [Notes log](#notes-log): what we found, with numbers, and file paths/commands so it can be reproduced. Facts that change a decision also go under [Decisions](#decisions).
- **Use subagents where they help.** Independent, parallelizable work with a clear brief and a checkable output goes to subagents: porting a contained module (one Liquid tag, one kramdown parser element), triaging a batch of golden-diff failures, drafting the per-IG upstream PRs, surveying a corpus slice. Each brief names the files to read, the acceptance check, and what's already ruled out. Results are verified (tests/diffs) before a task is marked done. Cross-cutting design and integration work stays in the main thread.
- **Monitor long-running work.** Corpus builds and full-corpus diffs run in the background. Track them under [Running / monitoring](#running--monitoring) with the command and where the output lands. Check them when notified, record results, and clear the entry.
- **The golden corpus is the referee.** "Works" means it matches real Jekyll output under the equivalence rule, not that it looks right. Every bug fix gets a minimal regression fixture.
- **Outward-facing actions need explicit approval** (opening upstream PRs, posting to Zulip/GitHub). Draft them here or in `work/prs/`, then ask.
- **Report failures plainly.** If a diff fails or a step was skipped, record it as it happened.

## Goal

Replace the Ruby/Jekyll stage of the FHIR IG Publisher with a Java implementation that supports **everything in active use on build.fhir.org today**. Motivation: the Ruby security-patch burden and Jekyll's slowness.
